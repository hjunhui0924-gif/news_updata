# 跨平台扩展预研说明 · X / RSS

更新日期：2026-09-19。状态：路线说明，尚未实现 X 或 RSS 接入。

## 结论先行

当前项目适合开始做 X 的可行性预研，不适合直接开发完整的 X 用户功能。GitHub 的关注管理、同步可靠性、站内阅读和至少 7 天持续试用仍是接入新平台前的准入条件。

RSS/Atom 是成本更低、授权更简单的候选平台；X 的内容价值更高，但需要单独验证官方接口权限、调用限制、费用、内容覆盖和账号授权。两者都不能因为现有 GitHub 连接器已经存在就被描述成“零改动接入”。

## 领域模型

跨平台实现统一以下概念：

| 概念 | 含义 | 例子 |
| --- | --- | --- |
| 平台 | 外部内容和身份服务 | GitHub、X、RSS |
| 来源 | 平台内可被跟踪的对象 | 仓库、开发者、X 账号、RSS Feed |
| 订阅 | 用户要求持续跟踪来源的关系 | 跟踪某仓库 Release、跟踪某账号原创内容 |
| 更新条目 | 阅读器展示的一次内容变化 | Release、X 帖子、Thread、Feed 文章 |
| 连接器 | 读取、校验和转换平台数据的适配角色 | GitHub Connector、X Connector、RSS Connector |

这些概念需要与平台的原始事件区分开。平台事件可能包含回复、转发、点赞或删除等变化，但不是所有事件都应该进入用户信息流。

## 当前架构评估

现有系统已经具备可复用能力：

- 用户级订阅、去重、已读、收藏和屏蔽状态。
- Worker 调度、队列投递、失败重试、限流等待和同步心跳。
- 原文、中文摘要、对照翻译、缓存和费用预算。
- 统一阅读器、来源筛选、详情页和移动端阅读。

仍然以 GitHub 为中心的部分包括：

- 更新类型目前主要是 Release 和新建仓库。
- 订阅类型目前主要是仓库和开发者。
- 外部身份、唯一键、授权状态和部分 UI 语义直接使用 GitHub 命名。
- 条目正文假设了 Release/README 一类 Markdown 内容。

因此，扩展前应先把“平台”和“来源身份”纳入统一语义，再添加具体连接器。不要先复制一份 GitHub 连接器和一套 X 专用 UI。

## X 预研范围

第一阶段只验证一个窄范围：

> 用户主动订阅一个公开 X 账号，应用读取该账号可合法获取的原创帖子和 Thread，转换为可阅读的更新条目。

暂不纳入：

- 推荐流、点赞、收藏、私信和社交图谱。
- 全量回复、转发和引用转发，除非它们是原帖上下文不可缺少的一部分。
- 私密账号、受限内容和绕过官方访问控制的抓取。
- 复杂媒体下载、视频转码和本地永久存储。
- 依据模型自动判断“重要帖子”并替用户改变订阅范围。

预研必须记录并验证：

1. 官方 API 的账号授权流程、权限范围和 token 生命周期。
2. 当前可用的用户/帖子/Thread 查询接口、分页方式和时间窗口。
3. 访问限制、计费方式、单用户成本和多用户扩展上限。
4. 编辑、删除、置顶、引用、转发和媒体的语义如何映射到更新条目。
5. 原始链接、作者身份、发布时间、正文和媒体链接是否能够稳定取得。
6. 401、403、429、404、删除内容和权限变化的可恢复行为。
7. 去重键、编辑后的正文更新、已读/收藏状态保留和旧摘要失效规则。

上述结论必须来自当前官方资料和最小真实测试，不能根据历史 API 经验推断。X 的价格、权限和接口可用性变化后，应重新评估，不在本文件中固定未经验证的数字。

## RSS/Atom 备选范围

RSS/Atom 可作为跨平台模型的第一枚低风险适配器：

- 来源是 Feed URL。
- 更新条目是 Feed entry。
- 用 ETag、Last-Modified 和发布时间减少重复读取。
- 先支持标题、摘要、正文链接、发布时间和作者；媒体按链接展示。
- 不需要用户 OAuth，但需要处理 Feed 失效、解析差异、重定向和站点限流。

RSS 不能代表所有平台能力，尤其不能替代 X 的账号授权和社交内容验证；它只适合验证统一来源、统一条目、统一阅读状态的抽象是否足够深。

## 分阶段路线

### P0：文档与准入（当前）

- 记录统一领域词汇和 GitHub/X/RSS 的边界。
- 完成 GitHub G2 的未完成项和 G4 持续试用；G3 当前约定的站内阅读闭环已完成，G1 关注对象管理已完成。
- 只做 X 官方资料、权限、成本和最小读取验证，不接入主 UI。

### P1：统一来源接口

- 定义平台、来源、订阅和更新条目的平台无关接口。
- 让存储唯一键能够区分平台和外部身份。
- 保持现有 GitHub 行为不变，先用 GitHub 适配器通过新接口。
- 为编辑、删除、媒体、正文类型和同步游标明确语义。

### P2：隔离适配器验证

- 用 fixtures 和可注入 transport 验证 X 或 RSS 连接器。
- 覆盖分页、限流、鉴权、去重、编辑、删除、媒体和恢复。
- 不改变真实用户数据，不默认添加订阅，不直接开启后台调度。

### P3：用户功能

只有 P0～P2 的验收条件满足后，才添加平台选择、来源管理、同步状态和阅读器入口。第一版平台功能必须有明确的支持范围和关闭方式。

## X 接入准入条件

- GitHub 主流程已经连续至少 7 天实际使用，并处理重复、延迟和支持范围内的漏抓。
- X 的官方授权、权限、调用限制和费用已用当前资料与最小测试确认。
- X 的第一版内容边界、隐私边界和删除/编辑语义已经写成可验收规则。
- 平台相关唯一键不会与 GitHub 或 RSS 冲突，且正文变更不会覆盖错误来源的 AI 结果。
- 连接器有单元测试、真实接口隔离测试、错误恢复测试和浏览器回归测试。
- 用户可以看到来源平台、同步时间、失败原因和当前覆盖范围。

## 暂不做的事情

本文件不承诺 X 已接入，不新增 X OAuth 配置，不新增 X 数据库迁移，不复制 GitHub 专用 UI，也不把 X 的内容抓取作为当前 Worker 的后台任务。
