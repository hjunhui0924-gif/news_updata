与现有 GitHub following 导入保持一致：读取关注后选择导入；源站以后新增关注可再次读取导入，已导入频道由 Worker 持续检查新视频。源站取消关注不自动删除站内历史或订阅，站内操作不修改源站关注。

## 自己的账号如何连接

1. 在 Google Cloud 自己的项目启用 YouTube Data API v3，配置 OAuth 同意页面；若应用处于测试状态，把实际授权账号加入测试用户。
2. 创建 Web application OAuth 客户端，把重定向 URI 配成 `<APP_URL>/api/platforms/youtube/callback`。默认本机为 `http://127.0.0.1:3000/api/platforms/youtube/callback`，注意主机与端口完全一致。
3. 服务端 `.env.local` 填入 `YOUTUBE_CLIENT_ID`、`YOUTUBE_CLIENT_SECRET`；保留稳定、至少 32 字符的 `BETTER_AUTH_SECRET`。凭据不能进入网页或 `NEXT_PUBLIC_`。已有库先备份，再执行迁移 0006 并重启 Web/Worker。
4. 在已有工作空间打开「添加订阅 → YouTube 关注」，连接账号，在 Google 官方页面完成授权。返回后直接进入该面板，再读取我的关注、勾选并导入。live 模式继续使用现有 GitHub 站内登录，YouTube 是该工作空间的平台连接；本机 Demo 无需 GitHub 登录。

`YOUTUBE_API_KEY` 不能读取个人关注，也不需要为了这条流程配置它。旧 Key/手动添加后端仅保留兼容，网页已换成账号与关注入口。后台 Node 必须可访问 Google 的授权、用户身份与 Data API；浏览器能访问 YouTube 不代表后台网络可达。

## 权限与恢复

- 请求 `openid` 和 `https://www.googleapis.com/auth/youtube.readonly`，不申请邮箱、订阅写入或视频管理权限。只用稳定 Google 身份识别当前连接，不按邮箱关联站内用户。
- 单次短期 state、HttpOnly/SameSite Cookie、PKCE、站内用户与 nonce 绑定，固定本站回调；取消/过期/失败只返回固定状态提示，不回显 code 或供应商细节。
- 访问与刷新凭据在 `platform_connections` 加密保存。并发续期只交换一次；开始交换后使用内部有界超时，先提交轮换后的凭据再传播调用者取消。配置变更、权限不足或授权撤销提示重新连接，临时故障短暂退避。
- 断开在同一用户锁内先尝试有界撤销，再清除本地凭据、待处理回调和关注预览。撤销失败仍断开本地，并提示到 Google 账号的第三方应用权限中移除；旧请求不能恢复连接。连接/明确断开后不回退服务器 API Key。
- 账号断开不删除订阅、历史、已读或收藏；后续更新等待重新连接。切换账号后旧预览不可再导入。

## 关注与浏览性能

- 只调用当前授权账号的 `subscriptions.list(mine=true)`，不接受任意用户名或搜索参数。每页最多 50 个，按需加载，最多 20 页/1000 个；预览 15 分钟有效，绑定站内用户和连接 generation。
- 同一次预览保留跨页选择；最近成功页可幂等重放，响应丢失后重试不再请求 Google、不重复推进页数。已订阅标记实时查询；新一次读取使旧预览失效。
- 选中频道最多 50 个一次批量读取元数据，不逐频道发外部请求；导入使用现有事务、平台唯一键、50 频道名额及任务 outbox。连接版本在事务内再次校验。重复导入不重复建订阅或同步任务，部分失败保留成功和剩余选择。
- 列表元数据长度有界，列表区限高滚动；手机弹窗保留标题和关闭按钮，只滚动内容区。加载时禁用重复请求、切换与关闭，错误可重试；空关注、缺配置、断开和权限失效都有明确状态。
- 已导入频道由现有 Worker 检查公开新视频，间隔默认 180 分钟。首次仅近 30 天最多 20 条历史，每轮候选窗口最多 250 项；简介纯文本、封面懒加载、详情按需获取，不嵌播放器、不下载字幕或音视频、不做视频全文 AI。
