# 平台适配层与 YouTube Demo

开始日期：2026-11-04。用户确认先建立适配层，再接入 YouTube，并为后续其他平台保留扩展位置。

本文记录先完成的手动频道/API Key 初版。之后用户明确需要连接自己的账号、读取关注，当前网页入口及 OAuth 配置已由 [YouTube 账号与关注导入](19-youtube-account-following.md) 更新；旧 API Key 只保留手动来源和开发诊断兼容。本文的初版验收与适配器设计仍保留为历史记录。

## 本轮范围与顺序

1. **适配层与 GitHub 迁移**（已完成并通过 review）：统一来源解析、更新分页、错误、平台身份、调度策略；保留 GitHub 既有数据、深链、条件请求和双流语义。
2. **YouTube 连接器**（已完成并通过 review）：官方 Data API，支持频道 ID / @handle / 规范频道地址；读取 uploads 列表，获取公开新视频元数据，隔离配额、超时和分页断点。只读取公开内容。
3. **订阅与阅读体验**（已完成并通过 review）：共用现有添加订阅、同步反馈、信息流、详情、已读收藏；视频简介与视频全文明确区分，封面懒加载，播放跳转原站。
4. **完整回归与交付**（已完成并通过 review）：真实 PostgreSQL 隔离测试、浏览器桌面/手机回归、构建、独立 review、日常库备份/升级/恢复验证及文档同步。

不包含字幕下载、音视频下载、转写、自动导入 YouTube 关注、推荐流、直播状态跟踪和 Bilibili 实现。没有配置 YouTube API Key 时提供明确配置错误，不把模拟接口测试描述成真实接口联调。

## 设计约束

- 平台决定身份命名空间；来源种类决定订阅对象。不同平台的相同外部 ID 不合并。
- 历史 GitHub 条目 ID 和外部键保持兼容，旧数据缺少平台时解释为 GitHub；新平台的条目外部键显式带平台前缀。订阅唯一键包含平台。
- 适配器负责平台输入、分页协议和正文补全；公共同步模块负责用户隔离、事务、去重、历史导入上限、阅读状态保留和任务投递。
- 游标由适配器解释，进度页码仅用于展示；平台凭据不进入订阅数据和客户端。
- 调度间隔按平台/来源策略确定，失败使用统一错误分类和重试时间；保留现有队列的有界并发。
- G4 继续暂缓，不阻塞本轮 Demo 开发；公开部署和长期真实使用仍需独立验收。

## 配置和使用

1. 在自己的 Google 项目启用 **YouTube Data API v3**，创建适用于服务端的 API Key；限制应与实际服务端环境匹配。
2. 在本机忽略的 `.env.local` 配置 `YOUTUBE_API_KEY`；`SYNC_YOUTUBE_INTERVAL_MINUTES=180` 为默认检查间隔，最小 15 分钟。不要使用 `NEXT_PUBLIC_`，不要把 Key 输入到网页、截图或提交到 Git。
3. 先停止旧 Web/Worker，现有数据库升级前执行 `pnpm db:backup`，再 `pnpm db:migrate`。可执行 `pnpm db:drill` 验证隔离恢复，再重启 Web/Worker；应用登录方式仍为现有 GitHub 登录/本地 Demo，YouTube 是内容来源，不是新增登录方式。
4. 可先运行只读检查：`pnpm youtube:check -- "@GoogleDevelopers"`（PowerShell 的 @handle 需要引号）。它检查频道和第一页公开元数据，不写数据库、不启动 Worker、不调用模型。服务器 Node 进程需要能访问 Google API，浏览器可打开 YouTube 不代表后台网络已可用。
5. 在「添加订阅 → YouTube 频道」输入频道 ID、@handle 或 `https://www.youtube.com/@handle` / `/channel/UC...` 地址。暂不解析单条视频、`/c/` 或 `/user/` 地址；缺少密钥时网页会明确提示并禁用提交。

## 内容、性能和覆盖边界

- 每轮最多读取 uploads 的前 5 页、250 项候选；整页早于滚动 30 天范围时提前结束，下一轮回首页。首次导入仍仅收录近 30 天最多 20 条历史，后续也受最近 250 项窗口限制，不承诺全历史或窗口之外无漏抓。
- 每用户最多 50 个 YouTube 频道，与 GitHub 作者名额分开计算；演示测试不消耗自己的 YouTube 配额。
- 元数据按最多 50 个视频批量读取；跳过删除/不可见、私有、尚未处理完成、未来发布和当前直播/预告条目。视频变为公开已处理后，只有仍处于支持窗口才可收录；已结束直播回放按普通公开条目处理。
- 标题、简介、发布时间、原站入口和允许的封面可用；简介按纯文本呈现，不作为字幕或转写。第一版不生成视频全文摘要/翻译。
- 信息流继续只返回预览，详情按需获取；封面懒加载，不嵌入播放器、不预加载音视频。已读、收藏、筛选和来源上下文共用现有流程。
- 每个外部请求最多等待 15 秒，取消向下传递；单任务工作量有界。临时限流记录 retryAt；配额不足保守等待 24 小时，同一进程/密钥的后续请求直接使用冷却结果。进程重启后仍保留订阅级 retryAt，进程内冷却不充当跨实例全局配额账本。
- 支持窗口内会更新已收录简介并保留阅读状态；暂不将源站删除同步成站内删除。元数据保留政策、删除传播、长期时效、多人共享配额和生产部署仍需后续专项验收。

## 后续平台如何扩展

新增平台时实现 `PlatformAdapter` 的来源解析、流定义、分页和正文补全，注册工厂、平台标识/显示信息及调度策略；来源类型和条目类型按实际需求增加。不要在公共同步事务里复制某个平台的 URL、鉴权、分页或正文抓取规则。

当前 GitHub 的 `repo` 字段和缺省平台保留用于旧数据兼容，适配器契约使用 `sourceName`。来源唯一键是用户 + 平台 + 来源种类 + 外部 ID；GitHub 旧条目键不变，其他平台条目键带平台前缀。凭据留在服务端 transport，已读/收藏和 AI 结果不会因平台外部 ID 相同而串用。

接口依据：[频道查询](https://developers.google.com/youtube/v3/docs/channels/list)、[uploads 列表读取](https://developers.google.com/youtube/v3/docs/playlistItems/list)、[视频元数据](https://developers.google.com/youtube/v3/docs/videos/list)。字幕读取权限另见 [captions.download](https://developers.google.com/youtube/v3/docs/captions/download)。官方文档核对不替代当前密钥和网络上的真实接口联调。
