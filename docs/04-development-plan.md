## 当前优先级：先做好 GitHub

用户明确要求先完善 GitHub，再做其他平台接入。目标是「打开一个网页，知道我关注的人和项目有哪些更新，并尽量直接读完」。以下为后续路线，本轮先完成下文的关注范围增量，不代表 G1–G4 全部完成。

| 顺序 | 模块 | 用户结果 | 验收重点 |
| --- | --- | --- | --- |
| G1 | 关注对象管理 | 容易导入关注的人，能区分作者、仓库与 Star 来源，明确每种订阅跟踪什么 | following 分页、重复/部分失败、名额限制、跟踪范围提示 |
| G2 | 同步可靠性与反馈 | 能分清尚未检查、正在检查、检查后无更新、同步失败；重启后继续同步 | 检查时间、队列/Worker 状态、限流/离线恢复、分页续扫、去重与状态保留 |
| G3 | 站内阅读闭环 | 从作者发现项目后可选择订阅版本；正文、图片、相对链接与对照翻译可用 | 作者到仓库订阅、Markdown 来源路径、图片加载失败、长内容/手机阅读 |
| G4 | 持续使用验证 | 实际关注对象连续使用时没有未解释的漏抓和重复，内容与状态可信 | 支持范围内与源站抽样比对、发布到入库延迟、原文/译文完整性、调用与费用记录 |

Trending 保留在今日精选，主线资源优先投入已有关注的更新体验。暂缓个性化推荐、自动质量打分和其他平台适配。GitHub 的 commit、PR、Issue、预发布等不因本次优先级调整自动全部加入信息流；需要按真实使用需求逐类确定范围，避免增加噪声。

### 下一模块 G1 的实施边界

现状核查：`GitHubConnector.following()` 固定读取第一页 50 人；预览接口输入用户名，导入接口按勾选用户名逐一创建作者订阅。作者订阅现已支持其拥有的新建公开非 fork 仓库，以及公开事件中由本人发布的正式 Release。仓库订阅跟踪正式 Release，不代表作者所有活动。

计划修改范围：`src/server/connectors/github.ts`、`src/server/connectors/github-user.ts`、`src/app/api/github/following/*`、`src/components/subscriptions-panel.tsx` 及相关共享类型和测试。

- 为 following 预览增加明确的页码与下一页契约，接入已有用户凭据读取逻辑；保留手动输入公开账号的入口。具体字段在模块开发时同步定义类型、接口和 UI，不假设现有接口已经提供。
- 登录账号的关注列表作为便捷入口，仍由用户选择导入对象；浏览列表不直接改变订阅。
- 跨页选择不丢失，已订阅对象可辨认，导入只重试失败项。完整浏览关注列表与可创建的订阅数量分开处理，明确现有 50 个作者订阅上限，不静默截断或默认提高上限。
- 作者和仓库订阅的覆盖范围就地说明，不把「作者关注」描述成自动订阅他的全部项目版本。
- 暂不把 GitHub 取消关注等同于应用取消订阅；自动跟随增删策略单独确定。

测试与停止条件：先验证 connector 分页/鉴权/错误契约，再做数据库幂等和部分失败测试，最后浏览器覆盖跨页勾选、重复项、空列表、名额不足、授权失败与手机操作。任一门槛未通过，先修复 G1，不推进 G2。

### 扩展其他平台前的条件

- GitHub 导入关注、同步更新、站内阅读、已读/收藏这一完整流程可重复使用。
- 承诺的更新种类和同步频率明确；失败能看见，恢复能验证，不承诺 GitHub 全部活动无遗漏。
- 至少连续 7 天实际试用，记录并处理重复、延迟和支持范围内的漏抓；时间尚未经过不能以单次测试代替。
- 依据实际试用结果判断 GitHub 日常阅读是否足够可用，再评估下一平台的内容覆盖、接入成本与限制。

每个后续模块仍执行实现、测试、审查的闭环。公开部署按用户选定的主机另行处理；暂不实现邮件、公开注册或收费体系。

### 本轮交付：区分项目更新与博主更新

按用户最新确认，先明确两种关注对象的行为：项目跟踪正式版本及已收录说明修改，博主跟踪新项目与本人发布的正式版本。连接器通过测试后，完成两条流的分页续查、多来源并发去重与阅读状态保留，再完成来源标识、跟踪范围说明和「查看更新」入口。审查补充重复同步历史上限、事务取消两项修复。

接口窗口、归属规则、验证结果和实际登录限制见 [本轮交付记录](11-github-following-scope.md)。following 完整分页、长期试用等仍在后续路线中。

后续已补充 G2 的授权恢复部分：令牌按需自动续期、跨进程串行轮换、临时失败重试、授权状态和重新连接入口。真实账号续期与同步恢复已验证，细节见 [授权续期记录](12-github-auth-renewal.md)，不代表 G2 全部可靠性场景已完成。
