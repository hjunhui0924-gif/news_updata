# 阅读体验与边界复核

日期：2026-11-05。范围是用户反馈涉及的导航、添加订阅、视频简介阅读与相关 API 边界，采用接口重点检查和布局轻量检查，不代表完成全项目审计或 G4 真实持续试用。

## 本轮判断与实现

| 建议 / 发现 | 处理 | 边界与体验考虑 |
| --- | --- | --- |
| 侧栏来源挤占导航空间 | 订阅来源默认收起，保留正在关注的数量及独立添加入口 | 原生按钮支持键盘；桌面与移动抽屉使用独立控制 ID；展开最多显示 6 项，更多来源从订阅管理查看；无订阅和全部暂停分别提示 |
| 切换添加方式时弹窗跳动 | 六种方式共用固定外框、标题和页签；内容区域内部滚动 | 桌面宽度最多 640px，高度最多 640px，受可视窗口约束；手机和横屏保留边距；滚动条预留空间；短表单提交按钮位于底部；沿用 Radix 焦点管理、Escape 和忙碌锁定 |
| YouTube 简介希望对照翻译 | 保留“视频简介”，增加“简介对照翻译”，按段落原文在上、中文在下 | 只处理作者简介，不读取字幕、下载视频或生成视频内容摘要；原文和译文作为纯文本显示，Markdown、HTML 字符串不会变成可执行内容 |
| 翻译需兼顾成本与流畅度 | 复用已有按需任务、缓存、预算、超时及内容版本校验 | 切换页签不发起翻译；处理中禁用重复提交；关闭 AI 时仍能阅读原文和已有译文；中文无需翻译，空白简介不排队，非中文超过 16000 字符在 API 入口拒绝 |
| 空列表仍可能被误判为异常 | 统一账号频道、关注、上传列表和视频详情的列表解析 | 只有明确 `pageInfo.totalResults = 0` 且无后续页时，才把省略 `items` 视为空列表；缺字段、非零计数、损坏条目及矛盾分页继续报错，不吞掉授权或网络失败 |

## 重点 Review

- **接口与内容边界**：简介翻译只开放 translation，summary 在提交入口和 Worker 两处继续拒绝视频内容摘要。没有扩大 OAuth 权限或增加平台搜索。
- **版本一致性**：视频译文纳入已有模型版本失效检查；落库仍检查用户及原文内容哈希，保留原文变更后的防覆盖保护。生成或读取不会重置已读、收藏。
- **错误恢复**：沿用请求超时和 busy 状态；服务关闭、空内容、超长内容、失败重试与缓存可读分别显示。YouTube 导入保留预览过期、换账号、部分失败和丢失响应重试处理。
- **布局与性能**：使用现有 React、Radix 和 CSS，不引入 UI 框架；折叠区按需展开；弹窗不靠 JavaScript 反复测量高度；视频封面和详情仍按需加载，没有引入播放器或整列表自动翻译。本轮没有重新做大规模滚动性能基准，不能据此给出新的帧率结论。

## 下一步真实体验

在页面读取自己的关注、选择频道导入，检查同步后的视频简介与信息流，再对一条外文简介手动发起翻译，查看段落对齐及实际译文质量。本轮未自动导入频道、未对真实简介发起模型请求，也未验证真实凭据续期、撤销授权或长期运行；G4 仍等待真实持续使用。

## 宽屏留白与字号追加复核

日期：2026-11-05。根据用户截图，原列表内容上限为 850px，标题 14px、简介 11px、时间 9px，手机简介进一步降至 10px，导致宽屏空间利用不足、辅助信息偏小。

- 列表改为占用主区域，内容上限提高到 1360px，并保留响应式边距。详情正文仍沿用原来的 850px 阅读宽度；列表简介限制文字行长，避免长句横跨整个宽屏。
- 列表标题采用桌面 18px、手机 17px，简介 15px、时间与标签 12px、关注来源 13px；提高辅助文字对比度，已读、未读和平台标识继续保留。
- 搜索与阅读布局切换合为一行，平台与内容类型筛选在宽屏并排、窄屏换行；移除重复数量及装饰性英文行，压缩工具区留白。手机筛选和布局按钮保持至少 44px 高；最窄屏的未读筛选使用带可访问名称的图标按钮。
- 长标题最多显示两行，悬停可查看完整标题，详情内容不截断；较长来源名称省略展示并保留完整提示。视频缩略图、来源和底部状态不会挤出列表边界。紧凑偏好继续隐藏简介。
- 保留服务端分页、分批渲染、`content-visibility`、缩略图懒加载和详情按需加载；没有新增依赖、平台请求、后台翻译或监听滚动的布局计算。本次没有重新测量大列表帧率，不把布局调整等同于性能基准提升。

验证：新增 `tests/e2e/reader-readability.spec.ts` 共 7 项，覆盖 320、390、768、1440、1920px，检查字号、宽屏利用率、首条内容位置、工具栏重叠、长视频标题、窄屏溢出、分栏与紧凑偏好；已查看桌面、手机和长标题截图。与阅读及上一轮体验回归合计 36 项全部通过，使用隔离 Demo 和专用 E2E 数据库。类型检查、受影响 TS/TSX 的 ESLint 和格式检查通过。截图保存于 `output/playwright/readability/`。
