# 本地备份、恢复演练与诊断

这套命令面向本项目的本机 Compose PostgreSQL。读取 `.env.local`，不会启动 Worker、调用 GitHub 或模型。远程数据库、带查询参数或 fragment 的连接 URL、端口与 Compose 不一致、数据库实例不一致时拒绝维护，防止连接参数覆盖已校验的主机或数据库。

```powershell
pnpm db:backup   # 只备份
pnpm db:drill    # 新备份 → 新建临时库恢复 → 核对 → 清理临时库
pnpm diagnose   # 配置存在与否、迁移、Worker 心跳、任务数、本地 Web 可达性
```

备份和 JSON 清单位于 `work/backups/`，名称中的时间为 UTC。清单记录 SHA-256、字节数、迁移版本、所有 public/pgboss 表的计数及条目状态指纹；不包含账号内容或连接 URL。**dump 本身包含账号和令牌等完整数据库内容**，请按敏感数据保管，不要上传、提交或对外分享。`work/` 和 dump 扩展名均被 Git 忽略。

备份使用只读、可重复读事务导出的 PostgreSQL snapshot。计数、状态指纹与 `pg_dump` 使用同一个快照，因此源库有并发写入时也不会把两个时刻的数据误判成恢复失败。

演练只恢复到本轮生成的 `news_restore_drill_<UTC时间>_<随机值>` 库，不能指定日常库为恢复目标。核对通过后以及普通失败路径均尝试清理本轮临时库和容器内临时文件，保留本机备份；清理失败会返回非零并在已生成清单中标记 `cleanup: failed`。取消会在当前外部命令结束后进入清理，外部命令最长等待 120 秒。断电、强制杀进程或 Docker 故障无法保证执行 finally，应先检查残留，再按本轮完整名称清理；不要删除 `news`、其他测试库或别人的演练库。

成功演练的清单应同时有 `restored: true` 和 `cleanup: complete`。`db:backup` 的 `restored` 为 false，表示只备份、未执行恢复验证。诊断时缺迁移会返回非零；仅 Worker 离线时数据库仍可阅读，ready 为 degraded。修复迁移后重跑 `pnpm diagnose`，再启动 Web/Worker。

2026-11-04 已对日常库执行实际演练：迁移前备份 675,054 字节，3 个迁移、159 条更新及其已读 25 / 收藏 3 / 静音 0 一致；应用 0004 后再演练，备份 677,008 字节，4 个迁移与相同条目状态均一致，孤儿条目 0。两种版本的临时库均清理完成。之后的迁移仍应先备份，再迁移，并可重新演练。

这里交付的是可重复的本机逻辑备份演练和脱敏诊断。定时备份、异机副本、保留期管理和生产灾难恢复尚未部署；本地磁盘损坏仍会影响本机备份。
