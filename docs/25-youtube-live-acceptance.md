## 2. 生命周期检查：临时状态已覆盖，平台内容仍有缺口

当前 `src/server/db/ephemeral-cleanup.ts` 明确只做临时状态过期清理。Worker 调用该维护函数，不等于已经实现视频正文、元数据及衍生产物的保留/删除策略。`src/server/platforms/youtube.ts` 的近期视频抓取窗口也不是历史内容的保留期限。

`disconnectYouTube` 已实现撤销尝试、本地凭据和账号信息清空、连接 generation 更新、待处理 OAuth 和关注预览失效。**它没有清除已有条目的提供方内容或译文。** 本地书签、已读状态和平台提供的数据需要分别分类，不能因为保留用户阅读记录而永久保留所有 API 数据。

本轮隔离探针使用一个唯一测试用户、一条模拟视频及其译文、一个关注预览，调用现有断开逻辑和维护函数，结果如下：

- 模拟 Google 撤销成功；本地连接为 `disconnected`，访问/刷新凭据清空，关注预览为 0。
- 调用现有维护函数并把判断时间推进 40 天后，条目仍保留 28 个字符的提供方正文和 19 个字符的衍生译文，已读/收藏均保留。
- 这证明现有维护任务不执行提供方内容清理。它不是“真实运行 40 天”的长期演练，也不意味着单纯保留条目行就是错误；关键缺口是未分类处理其平台正文和衍生内容。
- 探针在 `finally` 中删除自己的测试数据并恢复隔离库维护标记，未使用真实撤销接口。

现有实现尚不足以验收下列事项：

1. 内容获取/复核时间、授权归属、分类及刷新/删除截止时间；当前订阅同步时间不能替代每份平台内容的生命周期记录。
2. 所有存量平台内容的定期复核、刷新或删除，及视频删除、转私密、权限不足时的分类处理；不能只复核最近抓取窗口。
3. 站内断开、Google 设置撤销、令牌不可续期、账号切换的清理任务及重试；需防止迟到同步/AI 任务重新写入已删除内容。
4. 对应译文、AI 缓存、关注预览、导出和日志的处理范围，以及明确的删除入口、隐私说明。
5. 备份恢复后的删除记录重放与复核，避免恢复旧快照后重新展示已要求删除的平台内容。

官方依据为 [YouTube API Developer Policies](https://developers.google.com/youtube/terms/developer-policies) III.E.4 / III.E.5，本轮于 2026-11-05 直接读取官方页面核对。不同授权数据、非授权数据、用户主动撤销及外部撤销场景的条款范围不同，应据此分类实施；本报告不把所有数据和撤销情况概括成同一个删除期限。已有约束见 [数据生命周期与恢复边界](22-data-lifecycle-and-recovery.md)。

## 4. 后续开发和验收顺序

1. **分类及调度基础**：定义平台原始数据、衍生数据和用户状态的边界，补充获取/复核时间、授权范围、清理原因及删除记录；先在隔离库验证迁移，避免把当前真实历史一概删除。
2. **维护和撤销路径**：实现独立、可重试、按批处理的存量复核/清理；覆盖断开、外部撤销、失效、私密/删除和账号切换，对在途同步、翻译和重连实行版本隔离。
3. **体验及恢复**：展示清晰的删除/失效说明，按分类保留允许保留的用户状态；联动缓存、导出和备份恢复后的删除记录重放。
4. **先隔离再实际验收**：覆盖超时/429/临时错误不误删、分页/部分失败、重复任务、截止时间、跨用户和恢复重放，再安排受控真实撤销/重连及真实简介翻译检查。持续使用证据继续归入 G4。

每一步对接口、权限、并发和删除范围重点 review，确定性的文档与布局采用轻量检查。补齐以上实现并取得对应证据前，不把 E1 或完整数据生命周期标记为完成。
