# GitHub 授权自动续期与恢复

更新日期：2026-09-13。

## 问题与结果

本次真实登录的 GitHub 访问令牌有效期为 8 小时，网页登录会话则保持更久。旧同步代码直接读取数据库令牌，发现过期后要求重新登录，并把订阅和 Star 自动跟踪关闭。网页仍处于登录状态，后台却停止同步。

现在所有业务 GitHub 请求共享服务端续期模块。令牌距到期不足 60 秒或已经到期时，使用保存的刷新令牌按需换发；网页会话到期与 GitHub 授权失效分开处理。授权错误不再改变订阅或 Star 的启用偏好，恢复授权后由后续任务继续同步。

## 行为与接口

- 有效或没有声明有效期的令牌直接复用，不额外请求刷新接口。
- 同一账号的 Web/Worker 通过 PostgreSQL 事务锁串行续期，重新读取最新令牌。账号行锁同时协调重新登录回调的写入。
- 新访问令牌、轮换后的刷新令牌和有效期一起加密保存。请求方取消时，已经开始的轮换仍先保存成功响应，再返回取消，避免丢失已换发的刷新令牌。
- GitHub 返回 401 时，使用该次请求实际发送的令牌判断是否需要刷新，最多重试原请求一次。迟到的旧请求不会把其他请求换发的新令牌错误标为失效。
- 网络故障、服务端错误、异常响应保留原凭据，60 秒内不重复续期，之后随同步任务重试。明确的刷新令牌失效要求重新连接；错误状态关联令牌指纹，重新登录换发凭据后旧错误自动失效。
- 配置 `GITHUB_READ_TOKEN` 时不走 OAuth 续期。该凭据被拒绝时提示更新服务端配置，不要求用户重新登录，不关闭订阅。
- 禁用本应用未使用的 Better Auth `/get-access-token`、`/refresh-token`、`/account-info` 入口，避免另一条不受锁约束的刷新通路，以及向浏览器返回提供方令牌。

`Bootstrap.services.githubAuth` 返回 `state`、固定说明 `message`、访问令牌到期时间 `expiresAt` 和下次可尝试续期的时间 `retryAt`。不返回令牌、刷新令牌、指纹或提供方原始错误正文。状态包括：

| 状态 | 页面解释 |
| --- | --- |
| connected | 本地保存的授权未到期，按需自动续期；不等于持续联网检测 |
| refresh_pending | 即将到期或已到期，下次同步自动续期 |
| temporary_error | 临时续期失败，稍后自动重试 |
| reconnect_required | 重新连接 GitHub，保留订阅与阅读数据 |
| configured | 使用服务端配置的凭据，其有效性随请求检查 |
| configuration_error | 服务端凭据失效，需要更新配置 |
| public | 没有账号凭据，使用公开访问 |

设置页提供完整状态与「检查连接」入口，其他页面在需要处理时显示提示。状态变化时清除上一状态的操作错误，避免展示过时提示。「重新连接 GitHub」调用原登录流程并回到设置页，跳转只接受 HTTPS 的 github.com 地址。

`POST /api/github/connection` 使用原有 Origin、会话与账号允许名单校验，仅检查当前用户；按需续期并读取 GitHub 账号，返回上述安全状态。普通网页刷新只读授权元数据，不触发令牌轮换。

## 验证

- `pnpm test`：18 个文件、122 项通过。新增 11 项真实 PostgreSQL 授权集成测试、3 项请求重试单元测试；原有订阅测试改为验证授权失败后保留启用偏好。
- `pnpm test:e2e:auth`：9 项通过。覆盖授权等待续期、检查后恢复、临时失败、手机端重新连接跳转，并回归博主/项目、Star、Trending 和对照翻译。浏览器使用模拟接口，真实 OAuth 回调未再次人工登录；已查看手机截图。
- `pnpm lint`、`pnpm build`（Web 与 Worker）、`pnpm typecheck` 均通过。
- 本地无会话调用 `/api/github/connection` 返回 401；上述三个禁用的 Better Auth 入口返回 404；健康接口返回 200。
- 真实账号无需重新登录，使用已保存的刷新令牌成功续期，随后 GitHub `/user` 返回 200。新访问令牌到期时间为北京时间 2026-09-14 06:01:32 左右。
- 一次性恢复当前账号旧逻辑留下、错误文本明确为「GitHub 授权已过期，请重新登录。」的 28 个项目订阅与 Star 跟踪。恢复后确认 28 个订阅均启用且无错误，项目与 Star 均有新的成功同步时间，Worker 心跳正常。

## 限制

刷新发生在实际请求时，不是固定每小时轮换。网页登录会话仍有自己的有效期。用户撤销授权、刷新令牌到期、服务端密钥无法解密凭据时仍需要重新连接。如果 GitHub 已轮换令牌而网络中断导致响应完全丢失，或进程在保存前崩溃，也可能需要重新登录，无法通过本地事务消除跨系统的不确定性。

当前验证是一次真实续期和可重复的模拟故障测试，不代表已验证长期无人值守运行。应用仍为本机 MVP，公开部署前需配置 HTTPS、生产密钥与相应安全验证。
