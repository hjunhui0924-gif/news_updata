# 数据生命周期与恢复边界

日期：2026-11-04。适用当前个人 Demo；真实 YouTube 授权、平台数据删除/保留验收和公开部署仍属于 E1 的前置门禁，不因本轮维护功能通过而完成。

## 身份、编辑与删除

| 情况                | 当前行为与约束                                                                                                                                     |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 来源身份            | 用户 + 平台 + 来源种类 + 稳定外部 ID；旧 GitHub external key 保留，名称相同不合并。隔离旧 schema 迁移测试验证唯一键和已读/收藏不变。               |
| 同一事件有多个来源  | 仅按平台已验证的稳定事件 ID 去重，保留 sourceIds；标题或 URL 相似不合并，也不合并阅读状态。                                                        |
| 源站编辑            | 比较内容 hash / 源站时间；正文改变使旧 AI 失效，旧任务不能覆盖新内容；同内容的来源归属和本地已读/收藏保留。                                        |
| 暂不可见、404、限流 | 记录错误/冷却，不因单次失败删除历史；304 后的分页与检查点保持已有规则。明确源站删除的传播策略仍需按平台补验。                                      |
| 源站取消关注        | 后续再次读取可反映关注变化；当前不自动移除站内订阅或历史，不写回源站。                                                                             |
| 暂停、站内删除订阅  | 暂停停止后续同步；删除去除订阅，已有内容与用户阅读状态保留。GitHub Stars 自动订阅保留手动删除排除规则。                                            |
| 断开 YouTube        | 撤销/清除本地令牌与账号信息，改变连接 generation、作废待处理授权和预览。Demo 当前保留已导入订阅/历史；这不是正式平台数据保留策略，见下方 E1 门禁。 |

## 已实施的短期数据清理

- OAuth 待处理记录有效期 10 分钟；关注预览 15 分钟，过期不能重放。额度冷却只在截止时间前有效。
- Worker 调度中检查维护任务；完整清理后使用数据库时间标记限制为每小时一次，进程内每分钟检查。单次最多删除 1,000 条，达到批量上限则下一调度轮继续；事务 advisory lock 避免多 Worker 重复清理。
- 仅删除 `youtube-oauth:*`、`youtube-follow-preview:*` 中 expiresAt 为数值且已过期的记录，以及 `youtube:quota:*` 中已过期的数值截止时间。非预期格式保留供定位，不因强制转换失败阻塞调度。
- 不清理条目、连接、已读/收藏、AI 账目或在途任务。过期 nonce 指针不能脱离待处理 state 使用，仍由现有 OAuth 失效检查拒绝。维护失败只输出固定警告，延后重试，不打印 state key、令牌或记录正文。
- AI 版本新增可选 JSON 属性，无新 schema 迁移，不重写旧条目。启用模型时旧版/未标记的真实结果等待手动生成，读取不产生新付费任务。不同模型的缓存保留，费用不确定记录不自动删除。

## YouTube 正式接入前的 E1 门禁

2026-11-04 直接读取官方 [YouTube API Developer Policies](https://developers.google.com/youtube/terms/developer-policies) 的 III.E.4 / III.E.5：部分缓存数据要求 30 天内刷新或删除；通过客户端撤销授权后，相应授权数据须尽快且在 7 天内删除。Google 设置中撤销及令牌无法续期的关联数据也须按对应条款处理。这些条款的适用数据范围不同，不能概括为“断开就永久保留全部 API 数据”。

当前真实授权仍暂停，因此不在本轮对日常库盲目执行平台历史数据删除。E1 恢复前必须完成：

1. 区分授权关注列表、公开频道/视频元数据、用户自己写入的阅读/收藏与来源链接；记录获取时间、授权归属和刷新截止时间。
2. 实现并验证站内断开、Google 设置撤销、权限失效、账号切换的对应清理路径；不能依赖用户再次打开页面才清理。
3. 提供明确删除入口与隐私说明；刷新/删除 API 内容时，用户状态和书签应采用合规的数据分类处理，不以“收藏”为由保留必须删除的提供方数据。
4. 验证缓存、预览、导出、日志和备份的范围及恢复后再清理，不能通过旧备份重新引入已要求删除的数据。完成官方政策审阅及实际授权测试前不宣称正式 YouTube 支持或公开生产可用。

## 迁移、备份与恢复

1. 新迁移先在隔离 `_test` 库或临时 schema 验证旧数据、身份键、计数和阅读指纹；不能在日常库跑测试种子。
2. 日常变更前执行 `pnpm db:backup`；恢复演练执行 `pnpm db:drill`。脚本核对本地目标和 Docker 实例，通过一致性快照导出，在唯一命名的隔离库恢复；不会覆盖日常源库。
3. 验证迁移清单、所有相关表计数、条目已读/收藏/静音指纹、孤儿引用及备份 SHA-256，再删除隔离恢复库和容器临时文件。文件落在被忽略的 `work/backups/`，不得提交或公开。
4. 2026-11-04 本轮演练成功：6 项迁移、47 订阅、232 条目，已读 25、收藏 3、静音 0，阅读状态指纹 `3a0875517eb2696c3270176b51bb1c8d`，孤儿引用 0；恢复一致，临时资源清理完成。它是该一致性快照的结果，运行中的 Worker 后续计数可变化。
5. 不可逆 schema 变更采用经验证的备份恢复或前滚修复；未实现自动向下迁移。恢复目标切换必须停写并单独验证，演练成功不等于已经做过日常库回切。

## 未来导入/导出接口边界

- OPML 可表达标题、网页链接及标准 feed URL；GitHub Release/作者跟踪和 YouTube 账号关注没有可靠的标准 feed 等价时，必须明确跳过或提供单独扩展清单。
- 不能把 OAuth 权限、密钥、AI 依据、费用状态、任务检查点塞入 OPML。跨平台身份、已读/收藏、内容版本若要迁移，应有独立版本化清单和恢复验收。
- 导入需要 dry-run、来源身份校验、名额提示、幂等回执和失败重试；导出需要用户范围、脱敏和下载有效期。本轮仅定义接口需求，不新增 OPML 产品。
