### 4：数据与长列表性能（review 通过）

- `FeedPreview` SQL 投影不返回正文、译文、翻译块、哈希和摘要证据，仅保留摘要预览；bootstrap 的 feed 只带计数/游标，items 只序列化一次。
- 完整详情通过当前用户的单条 API 按需获取，深链 SSR 单独带 selectedItem；来源和优先级按当前订阅解析。
- 卡片采用原生 `content-visibility`；轻量状态缓存裁剪并保护选中/在途操作。
- 实测发现原搜索 JSON 解压扫描较慢，增加 0004：元数据生成搜索列、pg_trgm 索引、可见列表降序索引。生成列随内容更新，不需应用双写。
- `scripts/bench-feed.ts` 使用 `_test` 库、临时用户、10,000 条含约 8 KB 正文/译文数据，结束后删除自己的数据。12 次请求去掉前两次预热，报告余下 10 次；数据与指标为本机结果，不是线上 SLA。

| 指标                                           | 结果                                    |
| ---------------------------------------------- | --------------------------------------- |
| 30 条列表预览 / 完整条目 JSON                  | 22,295 / 295,947 字节（减少约 92.5%）   |
| 搜索 p95（原 JSON 搜索 / 生成列索引后）        | 808.46 / 13.50 ms                       |
| 首页 / 后续页 / 收藏未读筛选 p95               | 11.81 / 5.77 / 18.44 ms                 |
| 状态轮询 p95                                   | 3.52 ms                                 |
| 列表 EXPLAIN                                   | items_visible_feed_idx，Index Only Scan |
| 600 条已加载卡片滚动帧间隔 p95（首次实测）     | 17.6 ms                                 |
| 600 条搜索交互（含自动滚回输入框、防抖与断言） | 1,042 ms                                |

- 性能原始报告在忽略目录 `work/feed-benchmark[-baseline].json` 和 `work/browser-feed-performance.json`，可运行脚本复测当前版本；`--baseline` 只选择输出名称，不执行降级/删索引。
- 相关单元/数据库测试 14 项通过；作者来源相关一组 18 项通过；浏览器加精确网络重排和 600→630 条边界后共 9 项通过。
- review 后修复：mutation 期间的页/计数快照延后应用并在结束后恢复原分页意图；计数基线在请求前固定，详情先返回不影响差量；选中与在途状态受缓存淘汰保护。
