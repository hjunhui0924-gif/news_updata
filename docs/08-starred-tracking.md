# Star 仓库跟踪 · 增量交付

日期：2026-09-13。

## 使用方式

在「订阅管理 → 添加订阅 → 导入 Star」读取当前登录账号的公开 Star 仓库，也可填写其他公开用户名。勾选后导入，后台开始轮询正式 Release。

- 一页最多读取 50 个，支持继续加载；重叠页去重并保留用户已取消的选择。
- 已订阅仓库显示标记；重复导入不新增订阅或重复首轮同步任务，暂停的订阅也不会被自动恢复。
- 部分失败保留成功结果，失败条目保持勾选，支持直接重试。
- 导入中禁止关闭弹窗或切换标签，避免结果提示丢失。
- 总订阅上限仍为每用户 100 个仓库；网页按每批 20 个分批提交。
- 新增 Star 后需要再次导入；取消 Star 不自动取消本应用订阅。

跟踪范围是正式 Release，不包括 commit、PR、Issue 或任意文件修改。没有 Release 的仓库暂时不会产生版本消息。首次历史获取保持近 30 天、最多 20 条/仓库的规则，历史记录在「全部更新」阅读，不进入「今日精选」。未来希望在精选中看到仓库发布，可将订阅设为重点。

## 实现

- `GitHubConnector.starred`：公开 Star 列表分页与标准化，排除私有仓库，允许用户主动 Star 的 fork 仓库。
- `GitHubConnector.usernameById`：由已登录用户的稳定 GitHub ID 获取当前用户名。
- `POST /api/github/starred/preview`：带用户上下文的预览，标记该用户已订阅仓库。
- `POST /api/github/starred/import`：校验全部输入，最多 5 个并行来源读取，复用事务订阅、去重和任务出站记录。
- `StarredImport`：选取、分页、状态、分批提交与部分失败重试。

公开数据读取优先使用显式 GITHUB_READ_TOKEN；未配置时，在服务端使用当前用户已加密保存的 GitHub OAuth access token。核对账号允许名单与过期时间，通过 Better Auth 的公开 crypto API 解密，仅传给 GitHub API，不返回前端或写入环境文件。演示用户没有 OAuth 凭据时继续使用匿名公开访问。过期/解密失败的同步会暂停来源并提示重新登录；恢复后可手动恢复订阅。
