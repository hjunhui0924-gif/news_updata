# Star 仓库跟踪 · 增量交付

日期：2026-09-13。

## 使用方式

在「订阅管理 → 添加订阅 → 导入 Star」读取当前登录账号的公开 Star 仓库，也可填写其他公开用户名。勾选后导入，后台开始轮询正式 Release。

真实登录后也会自动跟踪当前账号：Worker 默认每 5 分钟检查公开 Star 列表，将新增仓库加入订阅。可在订阅管理的「Star 自动跟踪」查看状态、关闭/开启或立即检查。首次检查会导入当前列表内未订阅的仓库；手动导入适合选择其他公开账号的项目或恢复已排除的项目。

- 一页最多读取 50 个，支持继续加载；重叠页去重并保留用户已取消的选择。
- 已订阅仓库显示标记；重复导入不新增订阅或重复首轮同步任务，暂停的订阅也不会被自动恢复。
- 部分失败保留成功结果，失败条目保持勾选，支持直接重试。
- 导入中禁止关闭弹窗或切换标签，避免结果提示丢失。
- 总订阅上限仍为每用户 100 个仓库；网页按每批 20 个分批提交。
- 新增 Star 会在后续自动检查中导入；取消 Star 不自动取消本应用订阅。
- 在应用里取消仓库订阅会记录排除项，自动检查不会再加入；手动添加或导入该仓库会解除排除。暂停订阅也不会被自动恢复。
- 默认每 5 分钟轮询，非即时推送；数据库和 Worker 须运行。排队、分页、限流可能延长等待。Star 加入订阅后才开始首次 Release 获取，没有正式 Release 的项目不会凭空生成更新消息。

跟踪范围是正式 Release，不包括 commit、PR、Issue 或任意文件修改。没有 Release 的仓库暂时不会产生版本消息。首次历史获取保持近 30 天、最多 20 条/仓库的规则，历史记录在「全部更新」阅读，不进入「今日精选」。未来希望在精选中看到仓库发布，可将订阅设为重点。

## 实现

- `GitHubConnector.starred`：公开 Star 列表分页与标准化，排除私有仓库，允许用户主动 Star 的 fork 仓库。
- `GitHubConnector.usernameById`：由已登录用户的稳定 GitHub ID 获取当前用户名。
- `POST /api/github/starred/preview`：带用户上下文的预览，标记该用户已订阅仓库。
- `POST /api/github/starred/import`：校验全部输入，最多 5 个并行来源读取，复用事务订阅、去重和任务出站记录。
- `StarredImport`：选取、分页、状态、分批提交与部分失败重试。
- `star-sync.ts`：默认开启允许账号、调度去重、每任务最多 5 页、断点续查，复用事务订阅保存和首轮 Release 任务。
- `PATCH /api/github/starred/auto`：设置当前账号开关；`POST`：立即入队，复用会话、Origin 校验及限流期限。
- `StarSyncPanel`：开关、上次完成/新增数、下次检查、队列进度、错误和后台离线提示。
- `star_sync` 保存每用户检查状态；`star_sync_exclusions` 保存应用删除的仓库 ID，跨重启持久化。

开关切换重置扫描游标，并更换检查代次。已进入网络请求的旧执行不能在切换后写入订阅、游标或错误；订阅事务与开关共享用户级锁。尚未执行的排队任务及重试在执行时读取最新开关，关闭时不导入，重新开启后可重新读取当前 Star 列表。GitHub 429 期限在手动检查及切换开关后仍保留；401/404 会暂停并显示原因。每用户 100 个仓库的上限仍适用，达到上限时保留已导入结果及错误提示。

公开数据读取优先使用显式 GITHUB_READ_TOKEN；未配置时，在服务端使用当前用户已加密保存的 GitHub OAuth access token。核对账号允许名单与过期时间，通过 Better Auth 的公开 crypto API 解密，仅传给 GitHub API，不返回前端或写入环境文件。演示用户没有 OAuth 凭据时继续使用匿名公开访问。过期/解密失败的同步会暂停来源并提示重新登录；恢复后可手动恢复订阅。

- 单元/集成测试：10 个文件、65 项通过。新增自动检查 10 项，覆盖下轮发现新增 Star、调度去重、暂停/取消/手动恢复、用户隔离、断点续查、每任务页数上限、限流/过期暂停、关闭/重开并发、取消和数量上限。
- Star 浏览器测试：3 项通过，覆盖默认读取本人、已有订阅禁选、重叠分页保留选择、部分失败重试、导入中禁止切换/关闭、空列表和 390px 手机长名称布局；新增开关失败保持原状态、立即检查进度/完成、关闭禁止检查、限流和离线提示，无 pageerror。
- 浏览器使用本机 Chrome，在 3002 端口启动独立 demo 测试实例，单独使用 `.next-e2e` 构建目录，真实用户的 3000 端口登录实例保持运行。UI 的外部 Star 请求用可控响应验证，真实抓取另行实测。
- 类型检查、Lint 与 Web/Worker 构建通过。
- 实际账号已完成 GitHub OAuth 登录；已认证 GitHub API 实测额度为每小时 5000 次。
- 本轮实际读取并导入 28 个公开 Star 仓库，全部完成首次同步，失败 0；获取 43 条历史发布，来自其中 8 个仓库。这是本次快照，不是固定数据或完整历史承诺。
- 自动检查已通过真实 Worker 连续执行两轮，账号保持 28 个订阅，无重复新增和检查错误。新增 Star 的检测使用注入 transport 模拟列表变化验证，未代用户在 GitHub 执行 Star/unstar 写操作。

独立审查发现的选择重置、导入中途卸载和 OAuth 初始化绕过暂停处理三项问题均已修复并补充回归。

运行此次隔离浏览器测试：`pnpm test:e2e:starred`。依赖已启动的本地 PostgreSQL 和此前写入的 demo 样本；首次使用先按 README 初始化 demo，再切回 live。
